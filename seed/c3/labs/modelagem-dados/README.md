# Laboratório do C3.4 — Modelagem de dados
- Ambiente: PostgreSQL 17.12 (`postgres:17`, contêiner `c3-pg17`, 127.0.0.1:55432). Extensões usadas da própria imagem: `btree_gist`, `ltree`.
- Arquivos: `anomalias.sql` (tabela plana, três anomalias, normalização 3FN, reconstrução, 1FN, dependência transitiva), `relacionamentos.sql` (N:N, RESTRICT/CASCADE, 1:1, autorrelacionamento, domínios, polimorfismo), `escala.sql` (bigint x UUID com 300 mil linhas, desnormalização medida com 100 mil pedidos e 500 mil itens, trigger, evolução do esquema com 500 mil linhas), `padroes.sql` (exclusão lógica com índice parcial, validade com EXCLUDE, ltree, EAV) e as saídas `saida-modelagem.txt`, `saida-escala.txt`, `saida-padroes.txt` (os erros esperados aparecem no topo de `saida-modelagem.txt`, escritos em stderr).
- Reexecutar: `cat anomalias.sql relacionamentos.sql | docker exec -i c3-pg17 psql -U postgres -q`; depois `escala.sql` e `padroes.sql` (nessa ordem, no mesmo esquema `mod`).
- Limitações: tempos de uma máquina e de um contêiner; a segunda carga do experimento do trigger rodou em uma tabela já povoada (comparação aproximada); o tamanho da tabela antes do backfill não foi medido; a consulta recursiva de cadeia de gerentes do script foi escrita de forma confusa e seu resultado não é usado nas aulas.
- Não executado: row level security, NOT VALID/VALIDATE CONSTRAINT, UUIDv7 (sem função nativa no PostgreSQL 17), sharding, MySQL neste laboratório.
