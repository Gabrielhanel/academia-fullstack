# Laboratório do C3.6 — ORMs: Prisma e TypeORM
- Ambiente (2026-11-25): PostgreSQL 17.12 (`c3-pg17`, banco `ormlab`), Node.js 26, **Prisma 7.10.1** (`prisma`, `@prisma/client`, `@prisma/adapter-pg`), **TypeORM 1.1.3**, `pg` 8.23.1, `tsx` 4. Observação: a tag `latest` do pacote `prisma` apontava para `8.0.0-rc.35` (pré-lançamento); o curso usa o par estável 7.10.1 do `@prisma/client`.
- Arquivos: `prisma/schema.prisma` e `prisma/migrations/` (migração gerada por `prisma migrate dev --name inicial`), `prisma.config.ts` (Prisma 7: URL no config), `prisma-exp.ts` (N+1, estratégias de carga, erros, transações, SQL cru, paginação, Decimal) → `saida-prisma.txt`; `typeorm-exp.mjs` (EntitySchema, N+1, join x query, erros, transação, SQL cru, risco do `synchronize`) → `saida-typeorm.txt`; `orm-vs-sql.ts` (ORM x SQL x driver puro, leitura e escrita) → `saida-orm-vs-sql.txt`.
- Reexecutar: `npm i` (usando o `package.json` deste diretório), `docker exec c3-pg17 psql -U postgres -c "CREATE DATABASE ormlab"`, `export DATABASE_URL="postgresql://postgres:lab@127.0.0.1:55432/ormlab?schema=public"`, `npx prisma migrate dev --name inicial`, `npx prisma generate`, `npx tsx prisma-exp.ts`, `node typeorm-exp.mjs`, `npx tsx orm-vs-sql.ts`.
- Limitações: tempos de uma máquina e um contêiner (medianas de 7 repetições após aquecimento; a variação é grande em consultas curtas); o seed é pequeno (100 clientes, 500 pedidos, 1.500 itens); a comparação "1 consulta x 4 consultas" depende do volume e dos índices; o TypeORM foi usado com `EntitySchema` (sem decoradores) para evitar configuração do compilador; a causa da lentidão de `relationLoadStrategy: 'query'` no TypeORM (3 consultas, ~261 ms) não foi investigada.
- Não executado: MySQL com ORMs, Drizzle e outros ORMs, decoradores do TypeORM, `prisma migrate deploy` em CI, TypeORM migrations geradas pela CLI, Prisma Accelerate/Studio, banco de sombra (shadow database) em detalhe.
