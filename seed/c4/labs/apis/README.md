# Laboratório: APIs REST, GraphQL e WebSockets (curso C4.3)

- Ambiente: Node.js 26.13.1, Express 5.3.0, graphql 17.1.0, graphql-yoga 6.1.1, DataLoader 2.2.3, ws 8.23.0, Ajv 8.20.0 (+ ajv-formats 3.0.1), @apidevtools/swagger-parser 13.1.0, express-rate-limit 8.7.5, pg 8.23.1 e PostgreSQL 17.12 (contêiner `c4-pg`, `127.0.0.1:55433`, usado só em `paginacao.mjs`), em 2026-11-25.
- Reexecutar: `npm i`; `docker run -d --name c4-pg -e POSTGRES_PASSWORD=lab -p 127.0.0.1:55433:5432 postgres:17` (somente para `paginacao.mjs`); `node <script>.mjs`.
- Scripts e saídas: `http-rest.mjs` (verbos, status, ETag, If-Match, 406, 405, 428/412); `openapi.mjs` (validação da especificação, requisições com Ajv e teste de contrato da resposta); `graphql-exp.mjs` (N+1 e DataLoader, erros parciais, profundidade); `ws-exp.mjs` (autenticação no upgrade, maxPayload, heartbeat, broadcast, consumidor lento); `paginacao.mjs` (OFFSET x keyset em 1 milhão de linhas); `rate-limit.mjs` (express-rate-limit, janela fixa x balde de fichas); `idempotencia.mjs` (Idempotency-Key e versionamento); `gateway.mjs` (gateway com roteamento, autenticação na borda, timeout, disjuntor e contrato). Cada um tem seu `saida-*.txt`.
- Correções feitas durante o laboratório (e por que importam): o PUT "idempotente" inicialmente subia a versão a cada chamada (corrigido: sem mudança, mesma versão e mesmo ETag); o servidor WebSocket caiu com `RangeError WS_ERR_UNSUPPORTED_MESSAGE_LENGTH` por falta de um ouvinte de `error` no socket do servidor; o primeiro teste de paginação comparava posições desalinhadas (página 1.000 começa na linha 19.981); o balde de fichas de teste foi criado com um relógio antigo (resultado inicial errado); o cabeçalho `Deprecation` foi trocado de `true` (rascunho antigo) para a data estruturada da RFC 9745 (`@1767225600`), confirmada na RFC.
- Limitações: uma máquina; tempos de uma execução (a mediana de 7 em `paginacao.mjs`); o broadcast mede cliente e servidor no mesmo processo (a latência inclui a competição pela mesma thread); o consumidor lento foi simulado pausando o socket do cliente; o gateway é didático (não é um gateway de produção). Não executados: Apollo Server/Federation, subscriptions GraphQL, Socket.IO e SSE, escala horizontal de WebSockets (Redis pub/sub), Kong/Envoy/NGINX como gateways, OAuth no gateway, geração de clientes a partir do OpenAPI, ferramentas de contrato como Pact, e os cabeçalhos RateLimit com várias instâncias.
