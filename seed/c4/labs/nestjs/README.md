# Laboratório: NestJS (curso C4.2)

- Ambiente: Node.js 26.13.1, NestJS 12.6.1 (`@nestjs/common`, `core`, `platform-express`, `testing`, `microservices`), `@nestjs/bullmq` 12.0.2, `@nestjs/config` 12.1.1, BullMQ 6.7.10, ioredis 6.1.0, class-validator 0.15.1, class-transformer 0.5.1, rxjs 7.8.2, TypeScript 7.0.2 e Redis 8 (contêiner `c4-redis`, `127.0.0.1:57379`, usado só em `e4-micro.ts`), em 2026-11-25.
- Reexecutar: `npm i` (versões exatas do `package.json`), `npx tsc -p .` (gera `dist/`), `node dist/e1-di.js`, `node dist/e1b-circular.js` (termina com erro de propósito), `node dist/e2-pipeline.js`, `node --test dist/e3-testes.test.js`, `docker run -d --name c4-redis -p 127.0.0.1:57379:6379 redis:8` e `node dist/e4-micro.js`, `node dist/e5-modular.js`.
- Achados do ambiente (registrados porque mudam o código das aulas): o NestJS 12 é distribuído como **ESM** (o projeto precisa de `"type": "module"` e `module`/`moduleResolution` `nodenext`; com `commonjs` o TypeScript acusa TS1479); o TypeScript 7 **removeu** `moduleResolution: node10`; os decoradores usam `experimentalDecorators` e `emitDecoratorMetadata` (o `tsx`/esbuild não emite metadados de DI: compile com `tsc`); `NestFactory` chama `process.exit(1)` ao falhar a resolução de dependências, a menos que se passe `abortOnError: false`; o BullMQ 6 exige instalar `ioredis` à parte.
- Saídas: `saida-e1-di.txt`, `saida-e1b-circular.txt`, `saida-e2-pipeline.txt`, `saida-e3-testes.txt`, `saida-e4-micro.txt`, `saida-e5-modular.txt`.
- Limitações: uma máquina e uma execução por medida (a forma importa mais que os milissegundos); TCP e HTTP em `127.0.0.1`; as classes de uma experiência ficam no mesmo arquivo (em projetos reais, dependências circulares entre arquivos aparecem como `undefined` na importação). Não executados: `nest new` e a CLI, Swagger/OpenAPI, GraphQL no Nest, WebSockets no Nest, Fastify como adaptador, Passport e `@nestjs/jwt`, CQRS, `@nestjs/schedule`, `@nestjs/terminus`, ORMs no Nest, transportes Redis/NATS/Kafka/gRPC e testes e2e com banco real.
