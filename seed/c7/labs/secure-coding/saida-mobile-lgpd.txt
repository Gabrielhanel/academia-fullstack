== 2. Pseudonimização: SHA-256 sem chave x HMAC com chave (CPF tem só 10^9 possibilidades)
hash simples: CPF recuperado = true após 456790 tentativas em 3235 ms (141 mil/s, com o cálculo do dígito verificador, em Node)
extrapolação para TODO o espaço de 10^9 CPFs: ≈ 118 min em 1 núcleo, sem salt (GPUs são ordens de grandeza mais rápidas; não medido aqui)
HMAC com chave secreta: o atacante sem a chave não consegue validar candidatos (50.000 tentativas com chaves aleatórias: 0 acertos); o controlador, com a chave, gera o mesmo token para o mesmo CPF: true

== 3. k-anonimato em um conjunto sintético de 2.000 pessoas
quase-identificadores (idade, CEP completo, sexo): k mínimo = 1; 1998 de 2000 pessoas são ÚNICAS (reidentificáveis combinando as 3 informações); 1999 classes
generalizando (faixa de 10 anos, 2 primeiros dígitos do CEP, sexo): k mínimo = 1; únicos = 21; 283 classes
para k ≥ 5: 162 registros em classes menores que 5 seriam suprimidos (8.1% dos dados)
limite: k-anonimato não impede inferência por atributo (todos de uma classe podem ter o mesmo diagnóstico): checar diversidade (l-diversidade)
menor número de diagnósticos distintos por classe generalizada: 1
